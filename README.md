
# Модернизация сетевой инфраструктуры АО НПК «ПАНХ»

Репозиторий содержит программную модель отказоустойчивой корпоративной сети авиационной компании **АО НПК «ПАНХ»**, реализованную в среде эмуляции **Mininet** с использованием программируемых коммутаторов **Open vSwitch (OVS)**.

Проект демонстрирует интеграцию концепций **SDN (Software-Defined Networking)** в контуре ЦОД и **SD-WAN (Software-Defined WAN)** для динамического резервирования каналов связи с удаленными филиалами («Взлетная площадка») и внешним периметром.

---

## 1. Архитектура и структура сети

Сеть разделена на три функциональных сегмента, обеспечивающих непрерывность критических бизнес-процессов (передача метеоданных, координация полетов, телеметрия):

### 🏢 Главный Офис / ЦОД (HQ/DC)

* **Control Plane:** Централизованный SDN-контроллер (ONOS) и консоль управления SD-WAN трафиком.
* **Data Plane:** Коммутатор ядра `s1` (`s_hq`) на базе Open vSwitch.
* **Высокая доступность (HA):** Два пограничных Linux-маршрутизатора — `r1` (Основной) и `r3` (Резервный), объединенных перекрестными транками (*«Линк Резерва А»* и *«Линк Резерва Б»*) для исключения единой точки отказа.
* **Конечные узлы:** Выделенный сервер `h_srv`.

### 🛫 Взлетная площадка (Удаленный филиал)

* Интеллектуальный шлюз **SD-WAN CPE** на базе маршрутизатора `r2`, подключенный к локальному коммутатору `s2` (`s_br`).
* **Конечные узлы:** Метеостанция `h_meteo`, системы видеонаблюдения и координации полетов.

### 💻 Дистанционные сотрудники (Внешний периметр)

* Защищенный оверлейный L2-доступ на базе **ZeroTier VPN** для удаленных ИТ-специалистов и бухгалтеров.

## 2. Адресация и сетевые параметры (IP Management)

### Узлы и интерфейсы маршрутизации

| Узел | Интерфейс | IP-адрес / Маска | Назначение / Описание |
| --- | --- | --- | --- |
| **h_srv** | h_srv-eth0 | `10.1.10.10/24` | Корпоративный сервер в ЦОД (Default Route: `10.1.10.1`) |
| **h_meteo** | h_meteo-eth0 | `10.2.10.10/24` | Метеостанция на взлетной площадке (Default Route: `10.2.10.1`) |
| **r1** | r1-eth0 | `10.1.10.1/24` | Внутренний шлюз ЦОД (Основной) |
| **r1** | r1-eth1 | `192.168.1.1/30` | **Канал 1: Оптика (Основной)** — Стык с филиалом `r2` |
| **r3** | r3-eth0 | `10.1.10.2/24` | Внутренний шлюз ЦОД (Резервный) |
| **r3** | r3-eth2 | `192.168.2.1/30` | **Канал 2: 4G МТС (Беспроводной)** — Стык с филиалом `r2` |
| **r3** | r3-eth3 | `192.168.3.1/30` | **Канал 3: Спутник (Аварийный)** — Стык с филиалом `r2` |
| **r2** | r2-eth0 | `10.2.10.1/24` | Локальный шлюз филиала «Взлетная площадка» |

### Эмуляция физических каналов (TCLink)

> [!NOTE]
> Характеристики каналов связи настроены с помощью встроенных средств эмуляции задержек и пропускной способности Mininet.

* **Канал 1 (Оптика):** Скорость `100 Мбит/с`, задержка `10 мс`.
* **Канал 2 (4G МТС):** Скорость `30 Мбит/с`, задержка `40 мс`.
* **Канал 3 (Спутник):** Скорость `10 Мбит/с`, задержка `500 мс`.

## 3. Руководство по развертыванию стенда

Для запуска топологии в среде Mininet выполните команду в терминале виртуальной машины:

```bash
sudo python3 panh_topo.py

```

## 4. Сценарии тестирования отказоустойчивости

После запуска топологии и входа в интерактивную консоль `mininet>` выполните последовательный комплекс тестов для проверки автоматического резервирования трафика:

### Шаг 1. Проверка штатного режима (Основной канал: Оптика)

Проверьте первичную связность по основному оптическому линку:

```bash
mininet> h_meteo traceroute h_srv

```

### Шаг 2. Эмуляция Аварии №1 (Физический обрыв оптики)

Сымитируйте аварию на линии связи, принудительно отключив интерфейсы основного оптического линка между маршрутизаторами `r1` и `r2`:

```bash
mininet> r1 ip link set r1-eth1 down
mininet> r2 ip link set r2-eth1 down

```

Запустите повторную трассировку. Маршрут автоматически перестроится через Канал 2 (4G МТС) через резервный шлюз `192.168.2.1`. Задержка возрастет до ~162 мс, но передача данных продолжится без потерь:

```bash
mininet> h_meteo traceroute h_srv

```

### Шаг 3. Эмуляция Аварии №2 (Падение внутренних магистралей высокой доступности ЦОД)

Сымитируйте внутренний сбой линков высокой доступности (HA-стыков) между основным и резервным маршрутизаторами внутри серверной ЦОД:

```bash
mininet> r1 ip link set r1-int1 down
mininet> r3 ip link set r3-int1 down

```

Проверьте связность и прохождение трафика в условиях нарушения внутренней топологии ЦОД:

```bash
mininet> h_meteo traceroute h_srv

```

### Шаг 4. Эмуляция Аварии №3 (Каскадный отказ наземных сетей — Переход на Спутник)

Сымитируйте тотальное падение наземных каналов связи (отключение сотовой вышки 4G), переведя интерфейсы взаимодействия `r3` и `r2` в состояние `down`:

```bash
mininet> r3 ip link set r3-eth2 down
mininet> r2 ip link set r2-eth2 down

```

Выполните контрольную проверку. Маршрутизатор SD-WAN CPE переведет метеостанцию на самый глубокий эшелон защиты — Канал 3 (Аварийный Спутник) через `192.168.3.1`. Задержка составит ~1001-1004 мс, но критический полетный трафик будет доставлен:

```bash
mininet> h_meteo traceroute h_srv

```

### Шаг 5. Проверка пропускной способности аварийного эшелона

Проверьте реальную скорость обмена данными на самом узком спутниковом канале связи:

```bash
mininet> iperf h_meteo h_srv

```
